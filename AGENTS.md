# Project working instructions

- Build this analytics project with the user step by step, explaining each stage.
- The user has authorized creating the GitHub repository and making commits as the project changes.
- Commit completed, coherent changes after appropriate verification. Use clear commit messages describing the change; do not wait for a separate commit request.
- Push completed commits to the configured GitHub origin as checkpoints so the remote stays current. Never force-push or rewrite shared history without explicit authorization.
- Inspect the diff and staged file list before committing. Preserve unrelated user changes.
- Keep the virtual environment, raw dataset, processed datasets, credentials, and local SQLite databases out of Git. Include source attribution and reproducible download/setup instructions.
- Record unresolved verification gaps accurately. Do not claim that a notebook or chart was verified when it was not.
